# Архитектурные решения

## D-001. Local-first база и sync-ready сущности

MVP хранит пользовательские данные в IndexedDB через Dexie. Каждая изменяемая сущность имеет стабильный id, revision, timestamps, deviceId и tombstone; локальная outbox отделяет запись пользователя от будущей сетевой синхронизации. Это сохраняет скорость одного устройства и не заставляет позже ломать идентификаторы или формат конфликтов.

Будущая синхронизация использует optimistic concurrency: сервер принимает `baseRevision`, а конфликт возвращает обе версии для явного разрешения. Архивная копия и синхронизация — разные операции.

## D-002. Отдельный Vercel-origin

Верфь проектируется как отдельное Next.js-приложение на собственном origin. GitHub Pages недостаточен для защищённого OAuth callback и серверного секрета. Отдельный origin также не получает доступ к localStorage/IndexedDB других приложений: backup-адаптеры должны использовать явный экспорт, File System Access API или согласованный серверный протокол.

## D-003. Read-only GitHub App вместо клиентского токена

GitHub-интеграция использует GitHub App user access token. App устанавливается только на пять выбранных репозиториев и получает только `Metadata: read`, `Contents: read`, `Actions: read`. Код не передаёт client secret или access token браузерному JavaScript: токен хранится внутри AES-256-GCM-зашифрованной HttpOnly-cookie максимум восемь часов.

Доступ закреплён за immutable GitHub user id `46434977`, а не только за изменяемым login. Серверный код содержит фиксированный allowlist репозиториев и файлов; универсального GitHub proxy нет. Ответы `/api/github/*` помечены `private, no-store`, а service worker исключает `/api` и `/auth`.

## D-004. Публичный код не равен публичным данным

Репозиторий Верфи может быть публичным: это откроет исходный код, схему и интерфейс, но не IndexedDB устройства, GitHub access token или server environment variables. Безопасность зависит от отсутствия секретов в Git, строгой серверной границы и private-by-default экспорта.

Публичный репозиторий всё же раскрывает названия/URL проектов, seed-описания и архитектуру. Если даже эти сведения нежелательны, репозиторий следует оставить private. Flow runtime data, заметки и backup-файлы не входят в код ни при каком режиме репозитория.

Production-origin также не является общей авторизационной стеной: любой посетитель получает собственную изолированную IndexedDB и видит только очищенный seed. Он не получает данные, заметки или GitHub-сессию владельца; серверный GitHub sync дополнительно принимает только immutable owner id. Полностью закрытый UI потребует отдельного owner-gateway и не входит в local-first MVP.

## D-005. Наблюдаемые и ручные факты не смешиваются

GitHub sync возвращает нормализованный envelope с observedAt, источниками и ошибками по каждому репозиторию. Data layer применяет его как наблюдение; синхронизация одного проекта не стирает успешные данные остальных. Ручные поля и pinned facts не перезаписываются inferred-значениями.

## D-006. Два мобильных входа в одно PWA

Не создаются две сборки Верфи. Одна PWA имеет обычный обзор и быстрый `/dock`; start route читает device-local предпочтение. Manifest shortcuts дают отдельные точки входа. Это сохраняет единые данные и одну установленную иконку, но позволяет пользоваться Верфью как нативно-быстрой папкой приложений.

Нативный Android widget/TWA оценивается только после проверки реального трения: PWA shortcut и сохранённый start mode — первая ступень.

## D-007. Публичная витрина — отдельная очищенная проекция

После появления межустройственной синхронизации рабочая Верфь получает owner-auth boundary и канонический namespace `/app/*`. Авторизация связывает серверное состояние с единственным владельцем и закрывает рабочую библиотеку, даже если её главная мотивация — синхронизация между ПК и телефоном, а не многопользовательский режим.

Публичной остаётся только `/showcase`: отдельная очищенная проекция с полями `publicProfile`, явно включёнными владельцем. Она не читает основную IndexedDB, notes, maintenance, private repository metadata или backup status. Экспорт проекции должен быть allowlist-based, а не denylist-based. Физически витрина может жить в том же deployment, но её data boundary и сборочный артефакт остаются независимыми от `/app/*`.

## D-008. Flow backup исключён

Flow содержит чувствительные финансовые данные. До отдельного проекта по шифрованию, целостности и безопасному restore Верфь не запускает и не принимает его backups. В интерфейсе это осознанная политика `excluded · sensitive`, а не ошибка настройки.

## D-009. Один changelog, несколько представлений

Корневой `CHANGELOG.md` — канонический источник релизов Верфи. Скрипт генерирует типизированную историю для экрана версии; проверка требует совпадения package version, `APP_VERSION`, SW cache version и последнего релиза. Ручное дублирование истории в UI запрещено.
