# Верфь: продуктовая спецификация MVP

## Замысел

«Верфь» — личный центр контроля качества, обслуживания и развития экосистемы приложений. Он отвечает не только на вопрос «какие проекты существуют», но и на более полезные: что сейчас работает, что требует внимания, что изменилось за период, где есть технический долг и какие обязательства нельзя забыть.

Единственный пользователь и владелец данных — Budladislav. MVP работает local-first на одном устройстве; модель данных и экспорт заранее подготовлены к будущей синхронизации между телефоном и компьютером.

## Проекты MVP

| Проект | Репозиторий | Роль в экосистеме | Backup-позиция |
| --- | --- | --- | --- |
| Flow | `Budladislav/Flow` (private) | Активная финансовая система | Исключён: чувствительные данные |

| Fitness Tracker | `Budladislav/fitness-tracker` | Старейшее приложение, приоритет модернизации | Адаптер № 2 |

`ren2gar` и архивные репозитории не входят в Верфь.

## Функции MVP

- Обзор экосистемы: доступность, свежесть GitHub-фактов, просроченные обязательства, качество и последние релизы.
- Библиотека проектов и паспорт каждого приложения: назначение, даты, версия, стек, ссылки, возможности, профиль данных, заметки, релизы и оценки Werft Standard.
- «Док»: быстрый мобильный экран с крупными иконками и прямым открытием приложений без лишнего перехода через обзор. Стартовый экран выбирается отдельно на каждом устройстве.
- Сквозной журнал изменений: релизы всех приложений, фильтр по проекту и периоду, выгрузка за неделю, месяц или произвольные даты.
- Обслуживание: визуальные сроки хостинга, доменов, релизных проверок и резервного копирования; история выполнений.
- Приватные заметки и ячейки будущих проектов с этапом, тегами и следующим действием.
- Werft Standard v1: единый список проверяемых практик с результатом, доказательством и рекомендуемым исправлением.
- Полный экспорт/импорт базы Верфи с версией схемы, контрольной суммой и проверкой до записи.
- Безопасный read-only GitHub-мост: синхронизация только пяти разрешённых репозиториев и только известных технических файлов.
- Два changelog-представления самой Верфи: корневой `CHANGELOG.md` для Git и сгенерированный экран версии в настройках.

## Источники истины

| Данные | Источник истины | Поведение Верфи |
| --- | --- | --- |
| Репозиторий, стек, активность, deploy, технический changelog | GitHub | Наблюдает и обновляет с отметкой времени и доказательством |
| Заметки, планы, обслуживание, backup-журнал | Локальная база Верфи | Никогда не отправляет в GitHub |
| Ручная трактовка назначения/статуса | Пользователь | Не перезаписывает автоматически без явного решения |
| Будущая публичная витрина | Явно разрешённая проекция | Формируется отдельно; private-by-default |

Автоматическая синхронизация не должна превращать предположение в подтверждённый факт. Выводы о хранилище и backup-адаптере помечаются как inferred; ручные решения имеют приоритет.

## Граница MVP

В MVP нет общего серверного аккаунта, совместной работы, фонового доступа к браузерным данным других origin, автоматических backup-адаптеров и публикации публичной витрины. GitHub-мост — единственная серверная функция и не хранит долговременную базу: токен находится в зашифрованной HttpOnly-cookie ограниченное время.

## Критерии готовности

- Все пять проектов видны на desktop и мобильном экране, `Flow` корректно обозначен private и исключён из backup.
- Приложение можно установить как PWA; `/dock` открывается напрямую из shortcut.
- Локальные изменения сохраняются после перезагрузки; экспорт проходит проверку контрольной суммы и может быть восстановлен атомарно.
- Сквозной changelog фильтруется и выгружается без утечки заметок.
- GitHub sync не может обратиться к произвольному владельцу, репозиторию или пути; вход другого GitHub ID отвергается.
- `npm run check` проверяет release metadata, lint, types, tests и production build.
