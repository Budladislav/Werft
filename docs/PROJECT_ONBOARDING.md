# Подключение нового приложения к Верфи

Этот контракт позволяет новому проекту с первого релиза участвовать в общей истории, проверках качества и дальнейшем обслуживании. Сейчас регистрация проекта остаётся явным изменением allowlist и seed Верфи; автоматическое обнаружение всех репозиториев намеренно запрещено.

## Канонический changelog

Файл называется `CHANGELOG.md` и находится в корне репозитория. Один рекомендуемый формат для всех приложений:

```md
# Changelog

## [Unreleased]

## [0.1.0] — 30.08.2026 — Первый рабочий контур

### Добавлено

- Добавлен основной пользовательский сценарий.
- Реализован версионированный экспорт данных.

### Изменено

- Уточнена мобильная навигация.

### Исправлено

- Исправлено восстановление состояния после перезапуска.

### Безопасность

- Секреты исключены из клиентской сборки и журналов.
```

Правила:

- заголовок релиза: `## [MAJOR.MINOR.PATCH] — DD.MM.YYYY — Короткое название`;
- дата релиза — календарная дата фактической публикации;
- название короткое, предметное и понятное без номера версии;
- используются только секции `Добавлено`, `Изменено`, `Исправлено`, `Безопасность`; пустые секции не нужны;
- один bullet описывает одно законченное пользовательское или эксплуатационное изменение;
- версия в `package.json`, интерфейсе и changelog должна совпадать;
- старые ISO-даты `YYYY-MM-DD` Верфь читает, но новые записи оформляются единообразно.

## Нулевой день проекта

До первого production-релиза:

1. Создать публичный или private GitHub-репозиторий и основную ветку `main`.
2. Добавить `package.json` с canonical `version` и командой `npm run check`.
3. Создать root `CHANGELOG.md` по шаблону выше.
4. В `README.md` коротко описать назначение, технологии, источник истины данных, локальные/серверные хранилища и способ backup/restore.
5. Для PWA добавить manifest, иконки, installable shell, offline/update strategy и мобильную проверку.
6. Добавить GitHub Actions, запускающий `npm run check` до production deploy.
7. Заполнить GitHub description и homepage: Верфь использует их для паспорта и кнопки запуска.

## Регистрация в текущей Верфи

1. В установке GitHub App `budladislav-werft` добавить новый репозиторий в **Only select repositories**. Права остаются `Metadata`, `Contents` и `Actions: Read-only`.
2. Добавить имя репозитория в `GITHUB_REPOSITORY_CATALOG` в `src/lib/github/config.ts`. Для новых проектов используется только root `CHANGELOG.md`.
3. Если Vercel environment `GITHUB_REPOSITORIES` задан явно, дописать репозиторий и выполнить production redeploy.
4. Добавить проект и его начальные ручные поля в `src/data/seed.ts`: имя, slug, lifecycle, data sensitivity, ссылки, backup policy и стартовые оценки Werft Standard. GitHub затем заменит наблюдаемые факты, но не должен угадывать приватность и операционные правила.
5. Выпустить Верфь, открыть её с активной OAuth-сессией и нажать **Сверить сейчас**. Проверить версию, changelog, app URL, стек, последний commit и Actions.

Пока шага регистрации через UI нет: «ячейка идеи» помогает подготовить продукт, но не превращается автоматически в рабочий проект. Логичное следующее улучшение — мастер «Принять на стапель», который создаст локальную карточку, проверит контракт репозитория и выдаст точный checklist для GitHub App/Vercel без расширения прав доступа.
